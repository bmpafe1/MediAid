How the alert level is computed

OUTBREAK ≥ 2 RED-alert scans in the 7-day window from the same geohash cell. Indicates repeated high-acuity cases requiring immediate supervisor escalation.
ELEVATED Cough-positive rate > 35 % of total scans (with fewer than 2 red alerts). Elevated respiratory signal — watch for TB or viral surge.
NORMAL No outbreak threshold exceeded in the rolling 7-day window.
Window: Rows from the last 7 days (per recorded_at), grouped by village_geohash and data_source.
Small-cell suppression: Real field data (data_source = 'field') with fewer than 5 individual scans is not published — cells under this threshold are hidden to prevent reverse-identification of individuals in small villages.
Rainfall / climate anomaly trigger: Planned — not yet active. DHIS2 Climate App / ERA-5 / CHIRPS integration is scheduled for Quarter 2. All current alert levels are derived solely from scan outcome counts.
Alert level source: Computed server-side in the outbreak_radar_7d Supabase view; clients cannot supply or override it.

Data sources & privacy

Each row in this dashboard represents one anonymised scan event from a Community Health Aide (CHA) device. Only aggregate counts and a 4-character geohash (~39 km² cell) are transmitted — no patient names, identifiers, GPS coordinates, audio recordings, images, or biometric data ever leave the device.

Data sources: simulated_demo — prototype UI testing · training — CHA onboarding exercises · field_test — pre-deployment validation · field — live clinical data (subject to small-cell suppression).

Supabase RLS: The public anon key may only INSERT into the base table and SELECT from this view. Direct SELECT on the base table is forbidden for the anon role.
